JWT Working
JWT is compact, URL safe token used for authentication and authorization.
Instead of storing session data on server, all necessary info is stored inside the token.

JWT Features:
- Stateless (No Server Session)
- Scalable (Good For microservices)
- Fast

Refresh token set as cookies from spring boot code only as below:
@PostMapping("/login")
public ResponseEntity<?> login(@RequestBody LoginRequest request, HttpServletResponse response) {
	String accessToken = jwtUtil.generateAccessToken(request.getUserName());
	String refreshToken = refreshTokenService.createToken(request.getUserName());

	Cookie cookie = new Cookie("refreshToken", refreshToken);
	cookie.setHttpOnly(true);
	cookie.setSecure(true);
	cookie.setPath("api/auth/refresh");
	cookie.setMaxAge(7 * 24 * 60 * 60);
	
	response.addCookie(cookie);
	return ResponseEntity.ok(new AuthResponse(accessToken))
	
}

Structure of token?
It has 3 parts: Header, Payload, Signature
1. Header
Contains Metadata
{
	"alg":"HS256",
	"typ":""JWT
}

2. Payload
Contains user data(claims)
{
	"sub": "user123",
	"role": "admin",
	"exp": 12334434
}


3. Signature
Created Using base64UrlEncode etc
This ensures the token cannot be tampered with

Refresh Token
Why refresh token exists?
Access tokens are short lived.
But users dont want to log in every 15 minutes.
So, there is refresh token long lived 7 days which is used to get new access token.

Flow of access and refresh token 
1. Login
User logs in - server generates:
a. Access token(short life)
b. refresh token(long life)
{
	"accessToken":"abc123",
	"refreshToken":"xyz789"
}


2. Store Token(Client side)
Access token -> memory/localStorage
Refresh token -> HTTP only cookies(recommended)
Important: Refresh token should be more secure than access token.
-------------------------------------------------

Normal API request made
Authorization: Bearer <accessToken>
Server validates -> request succeeds

Access Token Expires
API returns 401 Unauthorized

Now use refresh token
Client call a special endpoints:
POST /auth/refresh
Sends Refresh token(cookie or body)

Server validates Refresh Token
Refresh token validated against token stored in database:
- it checks expiry and validates it.

If it is valid just generate new access (JWT) token and send it to user.
Also generate new refresh token and send it to user with JWT token. 

After that client retries API with new access token.
