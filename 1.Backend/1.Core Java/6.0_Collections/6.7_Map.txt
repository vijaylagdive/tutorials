Content1: Map
- Map is not child element of Collection. A separate interface in Java not inheriting any other interface.
- If we want to represent group of object as key value pair then we should go for map.
- Both keys and values are object only.
- Duplicate keys not allowed. Values can be duplicate.
- Each key value pair is called Entry.

Common Implementations:
1. HashMap(C) -> No order, fastest, allows one null key
2. LinkedHashMap(C) -> Maintains insertion order
3. TreeMap(C) -> Sorted order (ascending by key)
5. ConcurrentHashMap(C) -> Thread-safe and efficient

Common Example:
	Map<String, Integer> map = new HashMap<>();
        map.put("Vijay", 101);
        map.put("Amit", 102);
        map.put("Ravi", 103);

        // Get value
        System.out.println("Vijay's ID: " + map.get("Vijay"));

        // Loop
        for (Map.Entry<String, Integer> entry : map.entrySet()) {
            System.out.println(entry.getKey() + " : " + entry.getValue());
        }
{101=Vijay, 102=Amit, 103=Ravi}

Content2. Map specific methods:
1. Object put(Object key,Object value);
- If the key is new, it inserts the entry.
- If the key already exists, the old value is replaced.
Ex: map.put("Ravi", 103);

2. values(Map m);
- Returns a Collection of all values in the map.
Ex: Collection<String> values = map.values();

3. Object get(Object key);
- Returns the value associated with the given key.
- Returns null if the key is not present.
Ex: map.get(2)

4. Object remove(Object key);
- Deletes the key–value pair for the specified key.

5. boolean containsKey(Object key);
- Returns true or false.

6. boolean containsValue(Object value);
- Checks whether the map contains the given value.

7. boolean isEmpty();
- Returns true if size is 0.

8. int size();
- Returns the number of key–value pairs in the map.

9. keySet()
- Returns a Set of all keys in the map.
- e.g. Set<Integer> keys = map.keySet();

10. entrySet()
- Returns a Set of key–value pairs (Map.Entry objects).
e.g.
for (Map.Entry<Integer, String> entry : map.entrySet()) {
    System.out.println(entry.getKey() + " = " + entry.getValue());
}

11. clear()
- Removes All
Ex: map.clear();

12. putAll(map)
- Inserts all entries from the specified map into the current map.
- If a key does not exist → it is added
- If a key already exists → its value is overwritten

Content 4: HashMap
HashMap Class
- Underlying Data structure: HashTable
- Insertion order not preserved and it is based on hashcode of keys.
- Duplicate keys not allowed, Duplicate values allowed.
- Heterogeneous object are allowed for keys and values.
- Null is allowed for key but only once, Null is allowed for values for any number of times.
- Hashmap implements serializable and clonable but not RandomAccess.
- Hashmap is best choice if it is search operation.

Constructors:
1. HashMap h = new HashMap();// With default initail capacity 16. and Default fill ratio 0.75
2. HashMap m = new HashMap(int initial capacity);
3. HashMap m = new HashMap(int initial capacity, float fillRatio);
4. HashMap m = new HashMap(Map map);

Example:
	HashMap m = new HashMap();
	m.put("Chiranjivi",700);
	m.put("Balaih",800);		
	m.put("Venkatesh",200);	

Content4.1 Hashmap working
- Hashmap stores data using key value pairs. HashMap contains array of nodes.
- O(1) time complexity for put(key, value), get(key), remove(key)
- It works using hashing.

1. HashMap elements:
 1. Node: 
	Each node will have four fields.
	1. int hash
	2. key
	3. value
	4. next node index.

 2. Buckets: 
	- A bucket is an element of the HashMap array. 
	- It is used to store nodes. Two or more nodes can have the same bucket. 
	- If there are two or more nodes in same bucket, a link list structure is used to connect the nodes. 
	- Buckets are different in capacity. 

2. Inserting Element into map
Step 1: Compute Hash
- Hashing: Hashing is a process of converting an object into integer form by using the method hashCode().
- hashCode() returns integer that represents a hash value of an object.
- This integer is a hash, not an address, not memory location, not index.

Example: 
int hash = key.hashCode();	

- The integer value helps in indexing and faster searches.
- With that Hash code index value is calculated using indexing method.

Java further spreads the hash to reduce collision
hash = hash ^ (hash >>> 16);

Step 2: Calculate bucket index based in hash key
- index = hashCode(key) & (n-1).
- where n is the number of buckets or the size of the array. 
- This maps the hash to a valid bucket index.
- Let the key is Sunny, and hash code for "Sunny" is 63281940.
- To store the Key in the memory, we have to calculate index by using the index formula.
	i.e. index=63281940 & (16-1) = 4 
- 4 is the index where we have to store element

Step 3: Insert into Bucket
- If 4th bucket is empty → insert node
- If bucket already has entries → collision occurs

Collision Handling
If in that 4th bucket already a member present we have to calculate equality of the 
newly inserted element's key and existing element's key.

This is checked as below:

if (node.hash == hash && (node.key == key || key.equals(node.key)))

If it is true means it is duplicate member.
If it false element has to be added next to existing element.
There will be linked list if nodes are equal to or less that 8 or there will be a binary tree.
Hence both Keys will be stored at index 4 and bucket at 4th index will have 2 nodes.

equals() method: 
- This method is used to check whether 2 objects are equal or not. 
- This method is provided by the Object class. 
- You can override this in your class to provide your implementation. 
- HashMap uses equals() to compare the key to whether they are equal or not. 
- If the equals() method return true, they are equal otherwise not equal. 

3. Common issue in HashMap with custom object as key:
        Student s1 = new Student("Vijay",3);
        Student s2 = new Student("Vijay",3);
        Map<Student, Integer> map = new HashMap<>();
        map.put(s1,4);
        map.put(s2,3);
        map.forEach((key,value) -> {
            System.out.println(key + " = " + value);
        });

The data in both the classes is same still map will treat 2 object as different keys and will insert 2 entries.
To overcome this issue we need to override the class as below.
class Student {
    String name;
    int age;
    Student(String name, int age) {
        this.name = name;
        this.age = age;
    }

    @Override
    public boolean equals(Object o) {
     if (this == o) return true;
     if (!(o instanceof Employee)) return false;
     Employee e = (Employee) o;
     return id == e.id;
    }

    @Override
    public int hashCode() {
     return Objects.hash(id);
    }
}

4. Retrieving values:
map.get(new Key("Aman"));  

HashMap performs:
- hashCode() on the key
- Computes the bucket index
- Searches the bucket
- Uses equals() to find the exact key
- Returns the associated value

Step 1: Null Check
if (key == null)
    return getForNullKey();

HashMap allows one null key
Null key is always stored at bucket index 0


Step 2: Compute Hash Code
int hash = key.hashCode();

Then Java mixes the bits for better distribution:
hash = hash ^ (hash >>> 16);
- This reduces collisions caused by poor hash functions.

Step 3: Calculate Bucket Index
index = (n - 1) & hash;

Where:
n = current capacity (power of 2)
Bitwise AND ensures fast computation

Step 4: Locate the Bucket
Node<K,V> first = table[index];

Now there are three possibilities:

Case 1: Bucket is Empty
if (first == null)
    return null;

Case 2: Bucket Has Only One Entry
if (first.hash == hash && key.equals(first.key))
    return first.value;
- Value returned immediately

Case 3: Bucket Has Multiple Entries (Collision Case)
Now HashMap iterates:

- Collision Bucket Search
Linked List (Default)
Node<K,V> node = first;
while (node != null) {
    if (node.hash == hash &&
       (node.key == key || key.equals(node.key))) {
        return node.value;
    }
    node = node.next;
}
- equals() confirms the exact key
- Value is returned

Note:
HashMap retrieves a value by computing the key’s hash, locating the correct bucket, 
and then using equals() to find the exact key within that bucket before returning the associated value.

Content5: LinkedHashMap and Difference between HashMap and LinkedHashMap
- Child class of HashMap.
- Exactly same as hashmap including methodsa and constructors Except following differences.

Difference between HashMap and LinkedHashMap
UnderlyingDataStructure
HashMap: HashTable
LinkedHashMap: LinkedList + HashTable(Hybrid data structure)

Insertion order
HashMap: Insertion order is not preserved and it is based on hashcode of keys.
LinkedHashMap: Insertion order is preserved.

Version
HashMap: Introduced in 1.2
LinkedHashMap: Introduced in 1.4 

Note:
LinkedHashSet and LinkedHashMap commonly used for developing cache based applications.

Content6: SortedMap(I) and TreeMap(I)

- TreeMap is child interface of map.
If we want to represent group of key values pair according to some sorting order of keys then we should use sorted map.

Sorted map defines following specific methods:
1. Object firstKey(); //101
2. Object lastKey()//136
3. SortedMap headMap(Object key);//107: {101=A, 103=B, 104=C}
4. SortedMap tailMap(Object key);//107: 107=D, 125=E, 136=F
5. SortedMap subMap(Object key1, Object key2); // {103=B, 104=C, 107=D}
6. Comparator comparator() //null

Example:
101 - A
103 - B
104 - C
107 - D
125 - E
136 - F

Class TreeMap
- UnderlyingDataStructure: RED-BLACK Tree
- Insertion order: Not preserved and it is based on some sorting order of keys.
- Duplicate keys not allowed but value can be duplicate.
- If we are depending on default natural sorting order then keys should be homogeneous and comparable otherwise runtime exception
  ClassCasteException will be thrown.
- If we are defining our own sorting by comparator then keys need not be homogeneous and comparable.
- We can heterogeneous non comparable objects also.
- Whether we are depending on default natural sorting order or customized sorting order there are no restrictions for values.
- We can take heterogeneous non comparable objects also..
- Null Acceptance: For TreeMap null key gives NPE. From 1.6. Before that first null key was allowed.

constructors 4:
1. TreeMap t = new TreeMap()
Creates empty tree map with Default Natural sorting order.

2. TreeMap t = new TreeMap(Comparator c)
For customized sorting order.

3. TreeMap t = new TreeMap(SortedMap m)

4. TreeMap t = new TreeMap(Map m)

Example for Default natural sorting order:
	public static void main(String[] args) {
		TreeMap m = new TreeMap();
		m.put(100,"ZZZ");
		m.put(103,"YYY");
		m.put(101,"XXX");
		m.put(104,106);		
		//m.put("FFF","XXX");//CCE
		//m.put(null,"XXX");//NPE
	    System.out.println(m);
	}

output:{100=ZZZ, 101=XXX, 103=YYY, 104=106}

Example with customized sorting 
import java.util.*;
class MapDemo 
{
	public static void main(String[] args) 
	{
		TreeMap m = new TreeMap(new MyComparator());
		m.put("XXX",10);
		m.put("AAA",20);
		m.put("ZZZ",30);
		m.put("LLL",40);		
	    System.out.println(m);
	}
}

class MyComparator implements Comparator {
	public int compare(Object obj1, Object obj2)
	{
		String s1 = obj1.toString();
		String s2 = obj2.toString();
		return s1.compareTo(s2);//{AAA=20, LLL=40, XXX=10, ZZZ=30}		
		return s2.compareTo(s1);//{ZZZ=30, XXX=10, LLL=40, AAA=20}

	}
}
