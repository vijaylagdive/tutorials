Streams API Introduction:
To process elements present inside Collection.
To perform bulk operation on Collection object.
Stream API is a way to express and process collections of objects.
Enable us to perform operations like filtering, mapping, reducing and sorting.
A Stream is not a data structure — it’s a pipeline of operations on data.

Example:
import java.util.stream;
Stream s = c.stream();

Interfaces used for various operation.
filter(Predicate<T>)
map(Function<T,R> f);

Methods: stream(), filter(), map(), sorted(), collect(), count()

Basic stream structure
collection.stream()      // source
          .operation1()  // intermediate
          .operation2()
          .operation3()
          .terminal();   // terminal

Key Characteristics
- Declarative – focus on what to do, not how
- Functional – uses lambdas
- Lazy evaluation – operations run only when needed
- Supports parallelism – easy multi-core processing
- Does not modify the source

Stream Lifecycle:
1. Source
2. Intermediate
3. Terminal

1. Source:
List<Integer> list = List.of(1, 2, 3, 4, 5);

2. Intermediate Operations:
Intermediate Operations are the types of operations in which multiple methods are chained in a row.
Examples: filter, map, sorted, distinct, limit

3. Terminal: 
Terminal Operations are the type of Operations that return the result. 
These Operations are not processed further they just return a final result value.
Example: forEach, collect, reduce, count, findFirst

Examples:
1. map()
- The map method is used perform some operation on each element in stream and return the result stream.
- Used Interface: map(Function<T,R> f);

Example:

List square = number.stream().map(x->x*x).collect(Collectors.toList());

- The filter method is used for filtering the element in the stream based on the condition and return the result stream.
- Used Interface: filter(Predicate<T>)

Example:

List result = names.stream().filter(s->s.startsWith("S")).collect(Collectors.toList());

Q1. Stream vs Parallel Stream
In Java 8+, Stream and Parallel Stream are APIs used to process collections of data in a functional style. The key difference lies in how the operations are executed—sequentially or concurrently.
1. Stream (Sequential Stream)
A Stream processes elements one at a time, in a single thread, following the order of the data source.
Example
list.stream()
    .filter(n -> n % 2 == 0)
    .forEach(System.out::println);
Characteristics
- Uses one thread (the calling thread)
- Predictable order (important for ordered collections like List)
- Easier to debug
- Safe for stateful or non-thread-safe operations
- No performance gain from multi-core CPUs

When to use
- When the dataset is small
- When operations are I/O-bound or very fast
- When order matters
- When you use mutable shared state

2. Parallel Stream
A Parallel Stream splits the data into multiple chunks and processes them concurrently using multiple threads.
Internally, it uses the ForkJoinPool.commonPool().
Example:
list.parallelStream()
    .filter(n -> n % 2 == 0)
    .forEach(System.out::println);
list.stream()
    .parallel()
    .filter(n -> n % 2 == 0)
    .forEach(System.out::println);

- Uses multiple threads (based on CPU cores)
- Can be much faster for CPU‑intensive work
- Execution order is not guaranteed
- Harder to debug
- Can cause issues with shared mutable state
- Not always faster (thread overhead)

When to use
Large datasets
CPU-intensive operations
Stateless and independent computations
When order is not important
