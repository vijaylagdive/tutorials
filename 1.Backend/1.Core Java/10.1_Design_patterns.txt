Design Patterns
What are the design patterns:
- Design patterns are evolved as reusable solutions to the problems that we encounter 
  every day of programming.
- They are generally targetted at solving the problems of object generations and 
  integration.
- These generalized patterns act as template that can be applied to the real world 
  problems.

In Core Java, patterns are generally grouped into three categories.

I Creational Design Patterns
This type deals with object creation and initialization.
e.g. singleton, factory, Abstract Factory, Prototype etc.

1. Singleton Pattern
- Ensures only one instance of a class exists
- Used In: Logging, Configuration, DB Connection
Example:
class Singleton {
    private static Singleton instance;
    private Singleton() {}
    public static Singleton getInstance() {
        if (instance == null) {
            instance = new Singleton();
        }
        return instance;
    }
}
-------------------
2. Factory Pattern
- Creates objects without exposing the instantiation logic
- Used when object type depends on input
Example:

interface Shape {
    void draw();
}

class Circle implements Shape {
    public void draw() {
        System.out.println("Circle");
    }
}

class Square implements Shape {
    public void draw() {
        System.out.println("Square");
    }
}

class ShapeFactory {
    public static Shape getShape(String type) {
        if (type.equalsIgnoreCase("circle")) {
            return new Circle();
        } else {
            return new Square();
        }
    }
}
-------------------
3. Builder Pattern
- Used to create complex objects step-by-step
- Avoids long constructors

Example:
class User {
    private String name;
    private int age;
    private String email;
    private String phone;

    private User(Builder builder) {
        this.name = builder.name;
        this.age = builder.age;
        this.email = builder.email;
        this.phone = builder.phone;
    }

    public static class Builder {
        private String name;
        private int age;
        private String email;
        private String phone;

        public Builder(String name) {
            this.name = name;
        }

        public Builder age(int age ) {
            this.age = age;
            return this;
        }

        public Builder email(String email) {
            this.email = email;
            return this;
        }

        public Builder phone(String phone) {
            this.phone = phone;
            return this;
        }

        public User build() {
            return new User(this);
        }
    }

    // Getters
    public String getName() {
        return name;
    }

    public int getAge() {
        return age;
    }

    public String getEmail() {
        return email;
    }

    public String getPhone() {
        return phone;
    }    
}

Usage:
class MyTest {
    public static void main(String[] args) {
        User user = new User.Builder("Amit").build();
        System.out.println(user.getName());
    }
}

II. Structural Design Patterns
1. The Adapter pattern
- allows two incompatible interfaces to work together by acting as a bridge between them.
- It converts the interface of one class into another interface that a client expects.
Real example
- Your phone expects a USB port
- Wall socket provides different output.
- Adapter converts it - SO both can work together.

There are three main components
1. Target Interface -> What client expects
2. Adaptee -> Existing class with incompatible interface
3. Adapter -> Convert adaptee to target

When to use it:
- Working with legacy system
- Working with third party libraries
- When interfaces don't match
- Reusing existing code without modification.

III. Behavioral Design Patterns
These deal with communication between objects.

1. Observer Pattern
- It is used when one object (called Subject) needs to notify multiple other objects (called Observers)
- It notifies automatically whenever its state changes — without tightly coupling them.
Example: Youtube
Channel → Subject
Subscribers → Observers

Without Observer Pattern:
- Objects are tightly coupled
- Subject needs to manually call each dependent object
- Hard to add/remove listeners

Example:
import java.util.ArrayList;
import java.util.List;
interface Observer {
    void update(String message);
}
interface Subject {
    void registerObserver(Observer o);
    void removeObserver(Observer o);
    void notifyObservers();    
}
class YoutubeChannel implements Subject {
    private List<Observer> observers = new ArrayList<>();
    private String video;

    public void uploadVideo(String video) {
        this.video = video;
        notifyObservers();
    }

    @Override
    public void registerObserver(Observer o) {
        observers.add(o);
    }

    @Override
    public void removeObserver(Observer o) {
        observers.remove(o);
    }

    @Override
    public void notifyObservers() {
        for(Observer o: observers) {
            o.update(video);
        }
    }
}

class Subscriber implements Observer {
    private String name;
    public Subscriber (String name) {
        this.name = name;
    }
    @Override
    public void update(String video) {
        System.out.println(name + " Received notification: New Video - " + video);
    }
}

class ObserverMain {
    public static void main(String[] args) {
        YoutubeChannel channel = new YoutubeChannel();        
        Observer sub1 = new Subscriber("Alice");
        Observer sub2 = new Subscriber("Bob");
        channel.registerObserver(sub1);
        channel.registerObserver(sub2);
        channel.uploadVideo("Observer Pattern in Java");
    }
}
